\section{先看这里 - 一分钟明白整个流程}

\lead{不需要学编程。只需要知道内容放在哪里、点哪个按钮保存、去哪里检查结果。}

\begin{tcolorbox}[teal]
\begin{center}
\begin{tabularx}{\linewidth}{C c C c C}
\textbf{1. GitHub} & \Large$\longrightarrow$ & \textbf{2. Cloudflare} & \Large$\longrightarrow$ & \textbf{3. 网站}\\
放网站文件的文件柜 && 自动发布工具 && 访客看到的结果\\
\end{tabularx}

\subsection{平时更新只有四步}

\begin{tcolorbox}[gold]
在 GitHub 改一个文件 \(\rightarrow\) 点 \button{Commit changes} \(\rightarrow\) 等 Cloudflare \(\rightarrow\) 刷新网站。
\end{tcolorbox}

\subsection{开始前准备}

\checkline{茹婷有自己的 GitHub 账号。}\par
\checkline{茹婷有自己的 Cloudflare 账号。}\par
\checkline{JS Insights 提供的 ZIP 备份包已经保存。}\par

\begin{enumerate}
  \item 每次只改一件小事情。
  \item 保存后等 1-3 分钟，再检查网站。
  \item 只改本说明列出的文件。
  \item 不要把密码、验证码、API key 或私人资料写进 GitHub。
  \item Cloudflare 变红时先停止，把完整截图发给 JS Insights。

\begin{tcolorbox}[quiet]

GitHub、Cloudflare 和个人域名都放在茹婷自己名下。JS Insights 保留 collaborator 权限即可，不需要共享密码。
\end{tcolorbox}

\section{把网站放到茹婷自己的 GitHub}

\lead{有两个方法。方法 A 最短并保留完整历史，建议优先使用。方法 B 从 ZIP 新建一份独立副本。}

\subsection{方法 A - 转移现有 repository（推荐）}

\subsubsection{茹婷先做}
\begin{enumerate}
  \item 登录 \href{https://github.com/}{github.com}。
  \item 打开右上角账号菜单，复制准确的 GitHub username。
  \item 把 username 发给佳婧。
  \item 收到 GitHub 转移邮件后，在 24 小时内接受。
\end{enumerate}

\subsubsection{佳婧完成转移}
\begin{enumerate}
  \item 打开 \href{https://github.com/Jiajing-Sun/rutingwang-website}{目前的私人 repository}。
  \item 点 \button{Settings}。
  \item 在 \textbf{General} 页面滑到最下面。
  \item 在红色 \textbf{Danger Zone} 中找到 \textbf{Transfer repository}。
  \item 输入茹婷准确的 GitHub username。
  \item GitHub 要求确认时输入 \pathlabel{rutingwang-website}。
  \item 确认后，茹婷在邮件中接受。
\end{enumerate}

\begin{tcolorbox}[teal]
转移后，原 owner 通常会自动成为 collaborator。交付的 ZIP 仍是一份独立备份。
\end{tcolorbox}

\subsection{方法 B - 从 ZIP 新建私人 repository}

\begin{enumerate}
  \item 从 \href{https://desktop.github.com/}{desktop.github.com} 安装 GitHub Desktop，用茹婷账号登录。
  \item 解压 \pathlabel{ruting-wang-website-js-insights-handover-2026-07-21.zip}。
  \item 菜单选择 \textbf{File > Add Local Repository...}。
  \item 点 \textbf{Choose...}，选择解压后的文件夹。
  \item 如果提示不是 repository，点 \textbf{create a repository}。
  \item 名称用 \pathlabel{rutingwang-website}，branch 用 \pathlabel{main}。
  \item 在 \textbf{Summary} 填 \pathlabel{Initial website handover}。
  \item 点 \button{Commit to main}。
  \item 点 \button{Publish repository}，保持 \textbf{Keep this code private} 选中。
\end{enumerate}

\begin{tcolorbox}[alert]
\textbf{不要只把 ZIP 当作一个文件上传。}\par
Cloudflare 需要 ZIP 解压后的所有文件夹。最终 GitHub 地址应类似：\path{https://github.com/RUTING-USERNAME/rutingwang-website}。
\end{tcolorbox}

\section{用 Cloudflare Pages 发布网站}

\lead{Cloudflare 只需连接 GitHub 一次。以后 main branch 每次保存，网站都会自动重新发布。}

\begin{enumerate}
  \item 登录 \href{https://dash.cloudflare.com/}{dash.cloudflare.com}。
  \item 打开 \textbf{Workers \& Pages}。
  \item 点 \button{Create application}。
  \item 选择 \textbf{Pages} 标签。
  \item 点 \button{Import an existing Git repository}。
  \item 选择 \textbf{GitHub} 并授权 Cloudflare。
  \item GitHub 询问权限时，只选择 \pathlabel{rutingwang-website}。
  \item 回到 Cloudflare，选择该 repository，点 \button{Begin setup}。
\end{enumerate}

\section{个人域名和日常保存方法}

\subsection{以后连接个人域名}

没有域名时先用 \texttt{pages.dev} 地址完全没问题。

\begin{enumerate}
  \item Cloudflare > \textbf{Workers \& Pages}。
  \item 打开茹婷的网站项目。
  \item 点 \textbf{Custom domains}。
  \item 点 \button{Set up a domain}。
  \item 输入域名，例如 \texttt{rutingwang.com}。
  \item 按 Cloudflare 显示的 DNS 指示操作。
  \item 等状态变成 Active。
  \item 把 \texttt{SITE\_URL} 改成最终网址并重新部署。
\end{enumerate}

\begin{tcolorbox}[teal]
根域名可能需要使用 Cloudflare nameservers；\texttt{www} 子域名可能需要 CNAME。以 Cloudflare 当时显示的指示为准。
\end{tcolorbox}

\subsection{平时修改后的固定保存步骤}

\begin{enumerate}
  \item 在浏览器打开 GitHub repository。
  \item 找到本说明列出的文件。
  \item 点文件右上角的\textbf{铅笔图标}。
  \item 只改需要修改的文字。
  \item 点 \button{Commit changes...}。
  \item 填一句说明，例如 \pathlabel{Add October seminar}。
  \item 选择 \textbf{Commit directly to the main branch}。
  \item 点绿色 \button{Commit changes}。
  \item Cloudflare > 项目 > \textbf{Deployments}，等待绿色 \textbf{Success}。
  \item 刷新网站。
\end{enumerate}

\begin{tcolorbox}[quiet]
仍显示旧内容时，等一分钟再刷新一次。不要把同一修改连续重复提交。
\end{tcolorbox}

  \item 没有公开链接时保留 \texttt{"href": ""}。

\section{Talks - 添加第二条、修改和删除}

\subsection{添加第二条 Talk}

复制第一段从 \texttt{\{} 到 \texttt{\}} 的全部内容，粘贴在下面。两段之间必须有一个逗号：

\begin{lstlisting}
"items": [
  {
    "date": "2026-10-15",
    "title": "First talk title",
    "event": "First event",
    "venue": "First venue",
    "kind": "Invited seminar",
    "href": ""
  },
  {
    "date": "2026-09-03",
    "title": "Second talk title",
    "event": "Second event",
    "venue": "Second venue",
    "kind": "Conference presentation",
    "href": "https://example.com/event"
  }
],
\end{lstlisting}

最新的 Talk 放在最上面。

\subsection{修改或删除 Talk}

\begin{itemize}
  \item 修改：只改引号里面的文字。
  \item 删除：删除该条完整的 \texttt{\{ ... \}}。
  \item 还有两条时，两段之间保留一个逗号。
  \item 全部删除后，恢复成 \texttt{"items": [],}。
\end{itemize}

\begin{tcolorbox}[gold]
\textbf{JSON 最容易出错的四件事}
\begin{enumerate}
  \item 使用直的英文双引号：\texttt{"text"}。
  \item 不要删除字段名后面的冒号。
  \item 两条 Talk 之间有逗号，最后一条后面没有逗号。
  \item 不要修改文件底部的 \texttt{template}。
\end{enumerate}
\end{tcolorbox}

\subsection{最简单的支持请求}

不放心时，直接把下面六行发给 JS Insights：

\begin{lstlisting}
Date / 日期:
Talk title / 标题:
Event / 活动:
Venue / 地点:
Type of talk / 类型:
Public link / 公开链接:
\end{lstlisting}

\section{Publications 和其他网站内容}

\subsection{新增已经发表的 journal article}

打开 \pathlabel{src/data/publications.ts}。正式发表放在 \texttt{publications}；under review 放在 \texttt{workingPapers}。

复制一个相似区块，再替换为准确资料：

\begin{lstlisting}
{
  year: 2027,
  title: 'Exact article title',
  authors: 'Wang, R., & Coauthor, A.',
  venue: 'Journal Name',
  detail: '12(3), 100-120',
  doi: '10.1234/example.2027.001',
  featured: false,
  category: 'journal',
},
\end{lstlisting}

\begin{itemize}
  \item \texttt{doi} 只填 DOI，不要加 \texttt{https://doi.org/}。
  \item 作者顺序、期刊和卷期页码必须使用正式记录。
  \item 只有想放到 selected publications 时才使用 \texttt{featured: true}。
  \item 每条最后的 \texttt{\},} 不要漏掉逗号。
\end{itemize}

\begin{tcolorbox}[alert]
Publication 很容易写错。资料不确定时，把 DOI 或 publisher link 发给 JS Insights，不要猜。
\end{tcolorbox}

\subsection{账号安全}

\begin{itemize}
  \item GitHub 和 Cloudflare 开启 two-factor authentication。
  \item GitHub repository 保持 private。
  \item 个人域名注册在茹婷自己名下。
  \item ZIP 备份保存在两个安全位置。
  \item 给 JS Insights collaborator access，不要共享密码。
\end{itemize}

\section{出错时不要慌}

\subsection{修改成功的三个绿色信号}

\begin{enumerate}
  \item GitHub 中能看到刚才的修改。
  \item Cloudflare 显示绿色 \textbf{Success}。
  \item 刷新网站后能看到新内容。
\end{enumerate}

\subsection{Cloudflare 显示红色 failure}

\begin{tcolorbox}[alert]
\begin{enumerate}
  \item 停止继续修改。
  \item 截图红色 deployment 和完整 error text。
  \item 记下刚才的 GitHub commit message。
  \item 一起发给 JS Insights。
\end{enumerate}
新版本失败时，上一个成功版本通常仍会正常在线。
\end{tcolorbox}
