\section{Start here - the whole system in one minute}

\lead{You do not need to learn programming. You only need to know where the content lives, which button saves it, and where to check the result.}

\begin{tcolorbox}[teal]
\begin{center}
\begin{tabularx}{\linewidth}{C c C c C}
\textbf{1. GitHub} & \Large$\longrightarrow$ & \textbf{2. Cloudflare} & \Large$\longrightarrow$ & \textbf{3. Live website}\\
Website filing cabinet && Automatic publisher && What visitors see\\
\end{tabularx}
\end{center}
\end{tcolorbox}

\subsection{The normal update routine}

\begin{tcolorbox}[gold]
Edit one file on GitHub \(\rightarrow\) click \button{Commit changes} \(\rightarrow\) wait for Cloudflare \(\rightarrow\) refresh the website.
\end{tcolorbox}

\subsection{Before starting}

\checkline{Ruting has her own GitHub account.}\par
\checkline{Ruting has her own Cloudflare account.}\par
\checkline{The JS Insights ZIP package is saved in a safe place.}\par
\checkline{The accounts use an email Ruting expects to keep long term.}

\subsection{Five rules that prevent most problems}

\begin{enumerate}
  \item Change only one small thing at a time.
  \item After saving, wait about 1-3 minutes and check the live page.
  \item Edit only the files named in this guide.
  \item Never put passwords, verification codes, API keys or private personal information in GitHub.
  \item If Cloudflare turns red, stop editing and send one clear screenshot to JS Insights.
\end{enumerate}

\begin{tcolorbox}[quiet]
\textbf{The easiest long-term arrangement}\par
GitHub, Cloudflare and the personal domain should belong to Ruting. JS Insights can remain a collaborator, so support does not require sharing passwords.
\end{tcolorbox}

\section{Move the website to Ruting's GitHub}

\lead{Choose one method. Method A is shorter and keeps the complete history. Method B creates a separate copy from the ZIP backup.}

\subsection{Method A - transfer the existing repository (recommended)}

\subsubsection{Ruting does this first}
\begin{enumerate}
  \item Sign in at \href{https://github.com/}{github.com}.
  \item Open the top-right account menu and copy the exact GitHub username.
  \item Send the username to Jiajing.
  \item When GitHub emails a transfer request, open it and accept within 24 hours.
\end{enumerate}

\subsubsection{Jiajing completes the transfer}
\begin{enumerate}
  \item Open \href{https://github.com/Jiajing-Sun/rutingwang-website}{the current private repository}.
  \item Click \button{Settings}.
  \item Stay on \textbf{General} and scroll to the bottom.
  \item In the red \textbf{Danger Zone}, find \textbf{Transfer repository}.
  \item Enter Ruting's exact GitHub username.
  \item Type \pathlabel{rutingwang-website} when GitHub asks for the repository name.
  \item Confirm. Ruting then accepts the email.
\end{enumerate}

\begin{tcolorbox}[teal]
The original owner is normally added as a collaborator after a transfer. The supplied ZIP remains an independent backup.
\end{tcolorbox}

\subsection{Method B - create a new private repository from the ZIP}

\begin{enumerate}
  \item Download GitHub Desktop from \href{https://desktop.github.com/}{desktop.github.com} and sign in as Ruting.
  \item Unzip \pathlabel{ruting-wang-website-js-insights-handover-2026-07-21.zip}.
  \item In GitHub Desktop, choose \textbf{File > Add Local Repository...}.
  \item Click \textbf{Choose...} and select the unzipped folder.
  \item If it says this is not a repository, click \textbf{create a repository}.
  \item Use the name \pathlabel{rutingwang-website} and branch \pathlabel{main}.
  \item In \textbf{Summary}, type \pathlabel{Initial website handover}.
  \item Click \button{Commit to main}.
  \item Click \button{Publish repository} and keep \textbf{Keep this code private} selected.
\end{enumerate}

\begin{tcolorbox}[alert]
\textbf{Do not upload only the ZIP file to GitHub.}\par
Cloudflare needs the unzipped folders and files. The finished GitHub address should look like \path{https://github.com/RUTING-USERNAME/rutingwang-website}.
\end{tcolorbox}

\section{Publish with Cloudflare Pages}

\lead{Cloudflare connects to the GitHub repository once. After that, every saved change on the main branch is deployed automatically.}

\begin{enumerate}
  \item Sign in at \href{https://dash.cloudflare.com/}{dash.cloudflare.com}.
  \item Open \textbf{Workers \& Pages}.
  \item Click \button{Create application}.
  \item Select the \textbf{Pages} tab.
  \item Click \button{Import an existing Git repository}.
  \item Choose \textbf{GitHub} and authorise Cloudflare.
  \item Select only \pathlabel{rutingwang-website} when GitHub asks for repository access.
  \item Select that repository in Cloudflare and click \button{Begin setup}.
\end{enumerate}

\subsection{Enter these values exactly}

\begin{tcolorbox}[quiet]
\begin{tabularx}{\linewidth}{L{47mm}Y}
\toprule
\textbf{Cloudflare box} & \textbf{Value}\\
\midrule
Project name & \texttt{ruting-wang-academic}, or another available name\\
Production branch & \texttt{main}\\
Framework preset & \texttt{Astro}\\
Build command & \texttt{npm run build}\\
Build directory & \texttt{dist}\\
\bottomrule
\end{tabularx}
\end{tcolorbox}

If an \textbf{Environment variables} area is visible, add:

\begin{tcolorbox}[quiet]
\begin{tabularx}{\linewidth}{L{47mm}Y}
\toprule
\textbf{Variable} & \textbf{Value}\\
\midrule
\texttt{NODE\_VERSION} & \texttt{20}\\
\texttt{BASE\_PATH} & \texttt{/}\\
\texttt{SITE\_URL} & Final Cloudflare address, for example \texttt{https://ruting-wang-academic.pages.dev}\\
\bottomrule
\end{tabularx}
\end{tcolorbox}

\begin{enumerate}[start=9]
  \item Click \button{Save and Deploy}.
  \item Wait until the deployment shows green \textbf{Success}.
  \item Click \textbf{Visit site} and open every page once.
\end{enumerate}

\begin{tcolorbox}[gold]
\textbf{If the first deployment is red}\par
Check only these three settings first: branch \texttt{main}, command \texttt{npm run build}, directory \texttt{dist}. If they are correct, take a screenshot instead of changing random options.
\end{tcolorbox}

\section{Connect a personal domain later}

The free \texttt{pages.dev} address can be used until Ruting chooses a personal domain.

\begin{enumerate}
  \item Open Cloudflare > \textbf{Workers \& Pages}.
  \item Open the Ruting website project.
  \item Click \textbf{Custom domains}.
  \item Click \button{Set up a domain}.
  \item Enter the domain, for example \texttt{rutingwang.com}.
  \item Follow the DNS instructions shown by Cloudflare.
  \item Wait until the domain status becomes active.
  \item Change the Cloudflare variable \texttt{SITE\_URL} to the final address.
  \item Redeploy the latest version.
\end{enumerate}

\begin{tcolorbox}[teal]
For a root domain such as \texttt{rutingwang.com}, Cloudflare may ask to use Cloudflare nameservers. For a subdomain such as \texttt{www.rutingwang.com}, it may ask for a CNAME record. Follow the exact instruction displayed for that domain.
\end{tcolorbox}

\subsection{Everyday GitHub update routine}

\begin{enumerate}
  \item Open the repository in a browser.
  \item Open the file named in this guide.
  \item Click the \textbf{pencil icon}.
  \item Change only the required text.
  \item Click \button{Commit changes...}.
  \item Type a short message, for example \pathlabel{Add October seminar}.
  \item Choose \textbf{Commit directly to the main branch}.
  \item Click the green \button{Commit changes} button.
  \item Open Cloudflare > the project > \textbf{Deployments}.
  \item Wait for green \textbf{Success}, then refresh the live page.
\end{enumerate}

\begin{tcolorbox}[quiet]
If the old version is still visible, wait another minute and refresh once more. Do not commit the same edit repeatedly.
\end{tcolorbox}

\section{Talks - add, edit and remove safely}

\subsection{Add a second Talk}

Copy the whole first block from \texttt{\{} to \texttt{\}} and place the copy underneath. There must be one comma between the blocks:

\begin{lstlisting}
"items": [
  {
    "date": "2026-10-15",
    "title": "First talk title",
    "event": "First event",
    "venue": "First venue",
    "kind": "Invited seminar",
    "href": ""
  },
  {
    "date": "2026-09-03",
    "title": "Second talk title",
    "event": "Second event",
    "venue": "Second venue",
    "kind": "Conference presentation",
    "href": "https://example.com/event"
  }
],
\end{lstlisting}

Keep the newest Talk at the top.

\subsection{Edit or remove a Talk}

\begin{itemize}
  \item To correct a Talk, change only the words inside quotation marks.
  \item To remove one Talk, delete its complete \texttt{\{ ... \}} block.
  \item Keep one comma between two remaining Talk blocks.
  \item If no Talks remain, restore \texttt{"items": [],}.
\end{itemize}

\begin{tcolorbox}[gold]
\textbf{Four JSON rules}
\begin{enumerate}
  \item Use straight double quotation marks: \texttt{"text"}.
  \item Keep the colon after every field name.
  \item Put a comma between Talk blocks, but not after the final block.
  \item Do not edit the \texttt{template} block at the bottom.
\end{enumerate}
\end{tcolorbox}

\subsection{Simplest support request}

If editing feels uncertain, send JS Insights only this:

\begin{lstlisting}
Date:
Talk title:
Event:
Venue:
Type of talk:
Public link, if any:
\end{lstlisting}

\section{Publications and other content}

\subsection{Add a published journal article}

Open \pathlabel{src/data/publications.ts}. Published work goes in \texttt{publications}; work under review goes in \texttt{workingPapers}.

Copy a similar existing block and replace the values:

\begin{lstlisting}
{
  year: 2027,
  title: 'Exact article title',
  authors: 'Wang, R., & Coauthor, A.',
  venue: 'Journal Name',
  detail: '12(3), 100-120',
  doi: '10.1234/example.2027.001',
  featured: false,
  category: 'journal',
},
\end{lstlisting}

\begin{itemize}
  \item Enter only the DOI in \texttt{doi}; do not add \texttt{https://doi.org/}.
  \item Use the exact author order and final journal details.
  \item Use \texttt{featured: true} only when the article should be selected prominently.
  \item Keep the comma after the final \texttt{\},}.
\end{itemize}

\begin{tcolorbox}[alert]
Publication details are easy to misstate. If anything is uncertain, send JS Insights the DOI or official publisher link rather than guessing.
\end{tcolorbox}

\section{Troubleshooting without panic}

\subsection{A successful update has three green signs}

\begin{enumerate}
  \item GitHub displays the latest file change.
  \item Cloudflare shows a green \textbf{Success} deployment.
  \item The refreshed live page displays the new information.
\end{enumerate}

\subsection{If Cloudflare shows a red failure}

\begin{tcolorbox}[alert]
\begin{enumerate}
  \item Stop making more edits.
  \item Take one screenshot showing the red deployment and error text.
  \item Copy the GitHub commit message used for that change.
  \item Send both to JS Insights.
\end{enumerate}
The last successful website normally remains online while the failed new version is investigated.
\end{tcolorbox}
